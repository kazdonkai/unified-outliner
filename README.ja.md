# Unified Outliner

[English](README.md)

> Obsidianのノート内にある見出しセクションとリストの部分木を、周囲の構造を見失わずに再編成するためのプラグインです。

Unified Outliner は、単一のMarkdownノート内で構造を編集するための [Obsidian](https://obsidian.md) プラグインです。見出しセクション、リストの部分木、本文のブロックを、本文エディタ、専用の Outline Tree View、ブロックに焦点を当てて編集するための Partial Edit Pane から移動・レベル変更・コピー・閲覧・編集できます。また、同じノート内の見出しやブロックの埋め込み（`![[#見出し]]`、`![[#^block-id]]`）を、*ミラー* としてツリーから作成・管理できます。

**現在のバージョン:** 1.0.0 — 完全な変更履歴は [Releases](https://github.com/kazdonkai/unified-outliner/releases) をご覧ください。

**必要なObsidianのバージョン:** 1.8.7以上

**対象範囲:** 一度に扱うのは1つのノートです。ノート間で内容を移動・コピーすることはなく、ミラーが参照するのも同じノート内の見出しとブロックだけです。

## このプラグインの独自性

Obsidian標準のアウトラインは見出し構造を移動するのに適しています。また、リスト中心のアウトライナー系プラグインは個々のリスト項目を扱いやすくします。Unified Outliner は、その両方が同じノート内で必要になる場面、すなわち意味のまとまりを持つ見出しセクションと入れ子のリスト構造を、安全かつ可視的な単位として再編成することに焦点を置きます。

| 機能 | Obsidian標準アウトライン | リスト中心のアウトライナー系プラグイン | Unified Outliner |
| --- | --- | --- | --- |
| 見出し構造の移動 | 可能 | 実装による | ツリー選択と同期して可能 |
| 本文・子セクションを含む見出しセクション全体の移動 | 不可 | 主目的ではない | 可能 |
| 入れ子のリスト部分木の移動・親子関係変更 | 不可 | 多くの場合可能 | 可能 |
| 見出しとリスト項目を同じ構造ツリーに表示 | 不可 | 実装による | リスト表示を有効にすれば可能 |
| 選択したセクション／リスト部分木を別ペインで集中編集し、Markdownのマーカー・チェックボックス・番号を本文テキストと分離して表示 | 不可 | 実装による | 明示的な Apply と競合保護付きで可能 |
| 親項目の直接の子（追加・削除・並べ替え・インデント/アウトデント・インライン編集）をペインを離れずに編集 | 不可 | 実装による | leaf の子に限り、一度に1段階まで可能 |
| セクション・リスト部分木・本文ブロックを独立したコピーとして複製 | 不可 | 実装による | ツリーまたはコマンドパレットから、同じノート内で可能 |
| 同じノート内の埋め込み（ミラー）を構造ツリーに表示・作成・管理 | 不可 | 不可 | ミラー行の表示を有効にすれば可能 |
| ファイルごとのツリー折りたたみ状態の保存 | 不可 | 実装による | 複数の Outline Tree View 間で同期して保存 |

Unified Outliner は、全文検索、タスク管理、Dataview型の集計、AIによる文章作成を置き換えるものではありません。Markdownノートの信頼できる構造編集に専念します。

## インストール

### Community Plugins からインストールする（推奨）

1. Obsidianで **設定 → コミュニティプラグイン → 閲覧** を開きます。必要であれば制限モードを解除します。
2. **Unified Outliner** を検索し、選択して **インストール** します。
3. **設定 → コミュニティプラグイン** で **Unified Outliner** を有効にします。

ブラウザからは、[Unified Outliner の Community Plugins ページ](https://community.obsidian.md/plugins/unified-outliner)も開けます。

### ベータ版を BRAT で導入する

ベータ版や最近の開発版を試す場合は、[BRAT](https://github.com/TfTHacker/obsidian42-brat) を利用します。

1. **設定 → コミュニティプラグイン → 閲覧** から **Obsidian 42 - BRAT** をインストールして有効にします。
2. コマンドパレットで **BRAT: Add a beta plugin for testing** を実行します。
3. `https://github.com/kazdonkai/unified-outliner` を入力し、導入を確定します。
4. BRATの処理後、**設定 → コミュニティプラグイン** で **Unified Outliner** を有効にします。

BRATはリポジトリの更新を確認します。通常のカタログ公開前の変更も試したい場合に利用してください。

### GitHub Releases から直接ダウンロードする

特定バージョンを手動で導入する場合は、[GitHub Releases](https://github.com/kazdonkai/unified-outliner/releases) から `main.js`、`manifest.json`、`styles.css` の3ファイルをダウンロードします。

1. Vault内に次のフォルダがなければ作成します。

   ```text
   <あなたのVault>/.obsidian/plugins/unified-outliner/
   ```

2. ダウンロードした3ファイルすべてを、そのフォルダにコピーします。
3. Obsidianで **設定 → コミュニティプラグイン** を開き、**Unified Outliner** を有効にします。
4. すぐに表示されない場合は、Obsidianを再読み込みしてください。

### 更新する

Community Plugins と BRAT は、それぞれ更新を管理します。直接ダウンロードした場合は、`<あなたのVault>/.obsidian/plugins/unified-outliner/` にある同じ3ファイルを置き換え、Obsidianを再読み込みします。通常のVaultバックアップは、更新時にも保持してください。

## アウトラインノートの例

![iPadで並べて表示した Outline Tree View・Example outline note・Partial Edit Pane](docs/images/structured-note-overview.png)

このスクリーンショットは、iPad上で実際に使用している Unified Outliner を示しています。左に Outline Tree View、中央に開いた `Example outline note.md`、右に Basic Blocks セクションを編集している Partial Edit Pane が並んでいます。同様の構造は、このリポジトリの [`examples/Example outline note.md`](examples/Example%20outline%20note.md) で実際に試すことができます。お手元のVaultで開き、Outline Tree View の rename・move・delete・insert 操作を、段落・見出し・リスト・callout・blockquote にわたって試してみてください。

1. 見出しまたはリストを含むMarkdownノートを開きます。
2. コマンドパレットから **Open outline tree view** を実行するか、リボンのツリーアイコンを選びます。
3. **Outline Tree View** は、設定の **アウトラインツリーの既定のサイドバー位置** で選んだサイドバーに開きます（既定は右サイドバー。左サイドバーも選べます — 下記の「設定」を参照）。ノードをクリックすると本文の該当箇所へカーソルが移動し、本文のカーソル移動は対応するツリーノードに反映されます。
4. ノードを右クリックすると、移動、インデント、アウトデント、コピー、ミラーの作成、Partial Edit Paneでの編集を選べます。

Outline Tree View が右サイドバーにある状態で Partial Edit Pane を開くと、そのサイドバーが分割されて両方が同時に表示されます。ツリーを左サイドバーに置くと、Partial Edit Pane は右サイドバー単独で開くようになり、上のスクリーンショットのような3ペイン構成（ツリー・ノート・編集ペイン）になります。

リスト項目も見出しとともに表示したい場合は、プラグイン設定で **アウトラインツリーにリスト項目を表示** を有効にします。

## 使い方

### 構造を移動・レベル変更する

見出しまたはリスト項目にカーソルを置き、コマンドパレットから実行します。よく使う操作には **設定 → ホットキー** からショートカットを割り当てられます。

> 本書ではコマンド名・メニュー名を英語で示すことがあります。表示言語が日本語のとき、実際の画面では日本語名で表示されます（例: **Move block up** →「ブロックを上へ移動（カーソル位置の最小安全単位）」、**Copy block** →「ブロックをコピー」）。

| コマンド | 動作 |
| --- | --- |
| **Move block up / down** | カーソル位置の最小安全ブロック（見出しセクション、リスト部分木、通常の段落、またはカーソルが内部にあるcallout・blockquote・fenced code block・table全体）を、直前または直後の兄弟要素へ移動します。 |
| **Move section up / down** | カーソルがセクション内のどこにあっても、見出し・本文・子セクションを含む囲むセクション全体を移動します。 |
| **Indent block** | リスト部分木の親子関係を変更します。見出しセクションでは、構造上安全な場合に限り見出しレベルを1段下げます。 |
| **Outdent block** | リスト部分木を上位へ移動します。見出しセクションでは、構造上安全な場合に限り見出しレベルを1段上げます。 |
| **Delete block** | 現在の見出しセクションまたはリスト部分木を削除します。 |
| **Insert sibling after current block** | 現在の見出しセクションまたはリスト項目の後に、新しい空の要素を挿入します。 |
| **Insert child list item** | 現在のリスト項目の子として、新しい空のリスト項目を挿入します。 |
| **Move extended block up / down** | カーソルが内部にある場合に、**List + Callout** または **List + Quote** としてまとめられた拡張ブロック（設定 → 拡張ブロック を参照）を1つの単位として移動します。 |

同じ操作は Outline Tree View のノードを右クリックしても実行できます。実行できない操作はノートを変更しません。理由を表示したい場合は、プラグイン設定で **無操作時の通知を表示** を有効にしてください。Move block / Move section が実際に移動した対象は、ツリー内で一瞬フラッシュ表示され、設定を有効にすると移動内容を示す通知も表示されます。

### Outline Tree View を使う

ツリーは（どちらのサイドバーにあっても）単なるナビゲーションではなく構造編集のための作業ビューです。

- **見出しセクションをドラッグ＆ドロップ**して、セクション部分木を並べ替えられます。
- リスト表示を有効にすると、**リスト項目もドラッグ＆ドロップ**して、リスト部分木の並べ替えや親子関係変更ができます。
- **段落や、単体の callout・blockquote・fenced code block・table（表示している場合）もドラッグ＆ドロップ**して移動できます——セクションをまたいだ移動も可能で、必要に応じて前後に空行が自動的に補われます。デスクトップ・モバイルの両方に対応しています。
- セクションまたはリスト項目の行から、**新しいコードブロックや表を挿入**できます。**下にコードブロックを挿入**（Insert code block below。言語を選ぶか、info string を自由入力）または **下に表を挿入**（Insert table below。列数を1〜8から選ぶか、最小の2列テンプレートを使う）を選ぶと、挿入したブロックがそのまま Partial Edit Pane で開きます。挿入と最初の Apply は1回の Undo で取り消せます。挿入位置が一意に定まらない行では項目が「unavailable」と表示され、選ぶと理由が通知されます。
- ブロックの**コピー・複製・貼り付け**と**ミラーの作成**もできます。後述の「ブロックをコピー・複製する」と「ミラー（同じノート内の埋め込み）」を参照してください。
- ノードを**折りたたむ／展開する**ことで、ツリー独自の表示状態を制御できます。この状態はファイルごとに保存され、開いている Outline Tree View 間で同期します。
- 右クリックメニューから**文脈依存の操作**を使えます。折りたたまれたセクションは部分木として扱われ、展開されたセクションではノード単位の操作を選べます。
- **見出し・リスト項目・段落をその場でリネーム**できます。行をダブルクリックする（または行を選択してF2キーを押す、右クリックメニューから **Rename** を選ぶ）と、ツリー内でテキストを直接編集できます。Enterで確定、Escapeでノートを変更せずにキャンセルします。
- **モバイルでは**、タップで行を選択し、選択済みの行を再度タップするとリネームを開始、長押しでコンテキストメニューを開きます。
- セクション行とリスト行は、背景色や左端のストライプによって視覚的に区別できます。表示スタイルはプラグイン設定と、後述の Style Settings でさらに調整できます。

階層をまたいだ並べ替え――部分木を別の祖先の下へ親子関係変更したり、一度に複数の位置へ移動したりすること――はツリー側の操作であり、Partial Edit Pane 内からは行えません（後述の「Outline Tree と Partial Edit Pane それぞれの役割」を参照）。

### 段落を編集する

プラグイン設定で **本文段落も Outline Tree に表示する** を有効にすると、本文の通常の段落が ¶ マーク付きの読み取り専用ナビゲーションノードとして、見出しやリスト項目と並んで表示されます — 対象はトップレベルまたはセクション直下の段落のみで、リスト項目の中に入れ子になった段落は対象外です。表示されると、段落行も他の行と同様にその場でリネームでき、ドラッグ＆ドロップで（別のセクションへも）並べ替えでき、コンテキストメニューには **Move up/down**、**Move to top/bottom**、**Move before/after sibling…**、**Insert paragraph before/after**、**Delete paragraph**（確認あり）、および Partial Edit Pane で開く **Edit paragraph…** が追加されます。本文エディタ側でも、**Move block up/down** はカーソル位置の段落を移動可能な単位として扱い、**Edit paragraph at cursor** コマンドはその段落を直接 Partial Edit Pane で開きます。

### callout・blockquote・拡張ブロックを編集する

下記の拡張ブロックにまとめられていない単体の callout・blockquote は、ツリー上でそれぞれ独立したノードとして表示され、コンテキストメニューには **Move up/down**、**Delete**、および、セクションやリストサブツリーと同じ集中編集が行える **Open in Partial Edit**（ポップアウトも可能）が用意されています。デスクトップ・モバイルいずれでも、セクションをまたぐ移動を含めてドラッグ＆ドロップで並べ替えることもできます。

**List + Callout** と **List + Quote** は、Outline Tree の2つのグループ化規則です（設定 → 拡張ブロック を参照）。空行を挟まず1行で完結する list item の直後に callout または blockquote が続く場合、その2つを1つの折りたたみ可能な単位としてツリー上にまとめます。これらの規則は構造的なものであり、画像の埋め込み、OCRの内容、特定の callout type を必要としません。**Move extended block up/down**（コマンドパレットまたはツリーのコンテキストメニュー）はこのグループ全体を一緒に移動し、**Delete extended block** は単位としてまとめて削除します。拡張ブロック自身の行を Partial Edit Pane で開くと、ブロックの構造が分割可能な形である限り、list member とそれに続く callout/blockquote member をまとめて1回の Apply で編集できます（詳しくは後述の「リスト項目の構造化・マーカーフリー編集」を参照）。規則を無効にしても Markdown 本文は変更されません。対象の list item、callout、blockquote は、それぞれ通常の Outline Tree 表示規則に従って個別に表示されます。

新しい fenced code block や table は、セクションまたはリスト項目の行から **下にコードブロックを挿入**／**下に表を挿入** で追加できます（上記「Outline Tree View を使う」参照）。fenced code block（Mermaidを含む）と table は、内部的には安全な atomic 単位として認識されており、本文エディタ内でカーソルがその内部にある状態であれば、**Move block** を使ってブロック全体を移動することは引き続き可能です。設定で有効にすると（上記「設定」参照）、単体の fenced code block または table は Outline Tree 上に読み取り専用の行として表示され、そこからさらに専用の右クリックメニュー(またはツリーのドラッグハンドル、デスクトップ・モバイルいずれも対応)から、Move up/down（同一セクション内の隣接兄弟との入れ替え）・ブロック全体の削除・ドラッグ＆ドロップ（セクションをまたぐ移動を含む）・Partial Edit Pane での編集に対応します。fenced code block の開始・終了フェンス行はテキストエリアから非表示化されており、言語（info string）はエディタ上部の独立した選択UI（よく使う言語のドロップダウン＋自由入力の「Custom…」）で別途指定します。table は Partial Edit Pane を開くと **Raw** タブと **Table** タブが表示されます——Raw タブは表全体を生Markdownとして編集し（Apply時に表として最小限に妥当な構造かどうかを検証し、崩れる編集は拒否してノートを変更しません）、Table タブは各セルをインラインで編集できるフィールド、列ごとの配置切り替え、行の追加・移動・削除、列の追加・削除に対応し、いずれも同じ Apply で保存されます。

例えば、次の Markdown:

```markdown
- 史料画像への注記
> [!note] 転記上の注意
> 表記ゆれを原文どおり保持する。
```

は、ツリー上で次のように表示されます:

```text
◉ List + Callout
  - 史料画像への注記
  ▣ 転記上の注意
```

また、次の Markdown:

```markdown
- 史料本文の引用
> 村境は古来よりこの地点にある。
```

は、ツリー上で次のように表示されます:

```text
❖ List + Quote
  - 史料本文の引用
  村境は古来よりこの地点にある。
```

callout member には、単体の callout と同じ **▣** prefix が付きますが、blockquote member には付きません。

### ブロックをコピー・複製する

Outline Tree のセクション行、リスト項目の行（部分木全体）、単体の callout・blockquote・fenced code block・table の行、単体の段落の行には、コンテキストメニュー（モバイルでは長押し）に **ブロックをコピー**（Copy block）と **下に複製**（Duplicate below）があります。

- **下に複製** は、独立したコピーをブロックの直後に挿入します。セクションやリスト項目の場合は、部分木全体の直後に挿入します。
- **ブロックをコピー** は、そのブロックをコピー元として記憶します。ツリーの上に解除ボタン付きのバナーが表示され、コピー元の行は破線で囲まれます。以後はどの行にも **ブロックを貼り付け**（Paste block。その行の後）、**ブロックを上に貼り付け**（Paste block above）が表示され、セクション→セクション、リスト項目→リスト項目の場合は **ブロックを子として貼り付け**（Paste block as child）も表示されます。
- コピー状態は、貼り付けに成功したとき、または Escape キー、バナーの解除ボタン、**ブロックのコピーを解除**（Cancel block copy）で終了します。

同じ操作はコマンドパレットにもあり、カーソル位置の最小安全ブロック（**Move block** と同じ単位）を対象にします。

| コマンド | 動作 |
| --- | --- |
| **ブロックをコピー**（Copy block） | カーソル位置のブロックをコピー元として記憶します。 |
| **下に複製**（Duplicate below） | カーソル位置のブロックのコピーを、その直後に挿入します。 |
| **ブロックを貼り付け**（Paste block） | 記憶しているコピーを、カーソル位置のブロックの後に貼り付けます。 |
| **ブロックのコピーを解除**（Cancel block copy） | ノートを変更せずにコピー状態を終了します。 |

貼り付け位置と空行の扱いは、ドラッグ＆ドロップと同じ規則に従います。コピーは行を挿入するだけであり、コピー元を含む既存の行は一切書き換えません。順序付きリストの番号も振り直しません。コピー元の内部（自身の子孫の上、または自身の子として）、拡張ブロックの内部、frontmatter・コードブロック・callout の内部への貼り付けは、通知を出して拒否します。コピーした後にコピー元が変更された場合も拒否します。貼り付けできるのはコピー元と同じノートの中だけであり、拡張ブロックの行は貼り付け先にはなりますが、コピー元にはなりません。コピー・複製・貼り付けは、いずれも1回の Undo で取り消せます。

### ミラー（同じノート内の埋め込み）

*ミラー* とは、同じノート内の見出しやブロックを参照する、Obsidian の通常の埋め込み（`![[#見出し]]`、`![[#親見出し#子見出し]]`、`![[#^block-id]]`）のことです。Obsidian はこれを参照先の内容のライブ表示として描画します。ミラーの実体は埋め込み行そのものだけであり、Unified Outliner は独自のデータベースや隠れた状態を持ちません。そのため、ミラーを含むノートもプラグインなしで通用する素の Markdown のままです。

- **ツリーに表示する**: **アウトラインツリーにミラー（埋め込み）を表示** を有効にします（既定はオフ）。埋め込み行が読み取り専用の **⧉ Mirror: …** 行として表示されます。行をクリックする（または Enter キーを押す）と、他の行と同じく埋め込み行そのものへ移動します。参照先の見出しまたはブロックへ移動するには、行をダブルクリックするか、コンテキストメニューの **参照先へ移動**（Go to mirror source）を選びます。モバイルでは、選択済みの行をもう一度タップするたびに、参照先と埋め込み行が切り替わります。参照先が見つからないミラーには「（参照先なし）」、循環参照になっているミラーには「（循環参照）」が付き、いずれもテーマのエラー色で表示されます。オフのときは、埋め込み行は通常の段落として表示されます。
- **作成する**: セクション、リスト項目、単体の callout・blockquote・fenced code block・table、段落の行には **下にミラーを作成**（Create mirror below）があり、セクション行では **上にミラーを作成**（Create mirror above）になります。コマンドパレットには **ミラーを作成: カーソル位置のブロックの下に埋め込みを挿入** があります。ブロックの埋め込みはブロックの直後に置かれます（リスト項目の場合はリストを分断しないよう、リスト全体の直後）。セクションの埋め込みは見出し行の直上に置かれます。見出しの下はすべてそのセクションに属するため、下に置くとセクションが自分自身を埋め込むことになるからです。ブロック ID のないブロックには、Obsidian の慣例に従った位置に ID（`^uo-` に小文字英数字 8 文字を続けたもの）が自動で付きます。既存の ID は再利用し、見出しには ID を付けません。ID の付与と埋め込みの挿入は1回の編集であり、1回の Undo で取り消せます。循環参照になるミラーは作成を拒否します。参照先が見つからない場合や、参照があいまいな場合（同じテキストの見出しや同じ ID が複数ある場合。Obsidian と同じく最初の一致を使います）は警告を表示します。
- **移動・削除する**: ミラー行のコンテキストメニューには、**参照先へ移動**（Go to mirror source）、**ミラーを上へ移動**（Move mirror up）、**ミラーを下へ移動**（Move mirror down）、**ミラーを削除**（Delete mirror）だけが表示されます。移動は、同じセクション内の隣のブロックとの入れ替えです。削除は確認の後に埋め込み行だけを取り除き、その前後の空行を整理します（前後のブロックの間には空行を1行残し、ノートの先頭・末尾では残しません）。参照先の見出しやブロックと、そのブロック ID は一切変更しません。いずれも1回の Undo で取り消せます。
- **どこでミラーされているかを見る**: Partial Edit Pane で開いているブロックを参照するミラーがノート内にある場合、ペインの最下部に **このブロックを参照しているミラー: N 件** が表示されます。クリックするたびに、ノートのカーソルが次のミラーへ移動します。件数はノートの変更に合わせて更新され、ペインの下書きや Apply には影響しません。

ミラー行は、リネーム、ドラッグ、コピー、Partial Edit Pane での編集の対象になりません。ミラーに表示される内容を変えたいときは、参照先のブロック自体を編集してください。他のノートへの埋め込みは、ミラーとして扱いません。

### 選択したブロックに焦点を当てて編集する

コマンドパレットの **Open partial edit pane for current section** を実行するか、Outline Tree View の右クリックメニューから対応する項目を選びます。段落の場合は、**Edit paragraph at cursor**（または Outline Tree のコンテキストメニューの **Edit paragraph…**）を使うと直接ここに開けます。

**Partial Edit Pane** は、選択した見出しセクション、リスト部分木、単体の callout/blockquote、または拡張ブロックを専用エディタとして開きます。編集後に **Apply** を選ぶと、元のノートへ反映されます。ノートのMarkdownは常に唯一の正典（source of truth）であり、ペインの構造化コントロール（後述）はそれを映す表示にすぎず、ノートの実際の内容から乖離しうる別モデルではありません。ペインを開いた後に元の対象領域が変更された場合は、ノートを保護するため、競合する内容の反映を拒否します。この場合は対象を読み込み直し、上書きするのではなく変更内容を確認してください。このペインを未保存の変更なしに開いたまま、ノートが他の場所――別のペイン、Outline Tree、または本文エディタでの Undo/Redo――で変更された場合は、自動的に再同期します。この再同期には、その変更で最後の子が追加・削除された際に、leaf項目用エディタと親項目用エディタとの間で表示自体が切り替わる場合も含まれます。

段落・callout・blockquote・fenced code block・table にブロック ID（`^id`。たとえば **ミラーを作成** で付いたもの）がある場合、ID はエディタに表示されず、その下の **Block ID:** 欄に表示されます。欄を書き換えると ID を変更でき、空にすると ID を削除できます。Apply すると、ID は元と同じ場所（最終行の末尾、またはブロックの後の独立した行）に書き戻されます。この欄は ID のあるブロックでだけ表示され、英数字とハイフン以外を含む値は受け付けません。ID を変更すると、同じノート内でその ID を埋め込んでいるミラー（`![[#^id]]`）も同じ編集の中で書き換わります（1 回の Undo で戻ります）。ID を削除した場合、それらのミラーは参照先を失い、その旨の警告が表示されます。他のノートのリンクや埋め込みがその ID を参照している場合は、参照が壊れた可能性があるという警告が表示されます。他のノートは変更しません。

祖先のパンくずナビゲーションと Subtree Navigator を使うと、ペインを閉じずに親ブロックへ戻ったり子ブロックへ入ったりできます。ペインはノードのコンテキストメニューから別ウィンドウにポップアウトすることもでき、未保存の変更がある状態で離れようとすると確認を求めます。

#### リスト項目の構造化・マーカーフリー編集

対象となる単体のリスト項目では、ペインは直接入力しても意味を持たないMarkdown構文――list marker（`-`/`*`/`+`）、task-listのチェックボックス（`[ ]`/`[x]`）、順序付きリストの番号とその区切り文字――を隠し、項目本体のテキストのみを表示します。該当する場合は、その横に小さなチェックボックスまたは番号コントロールも表示されます。Apply は常に元のマーカー・チェックボックス構文・区切り文字・インデントを正確に復元するため、実際に編集した部分だけがMarkdownに反映されます。

これが適用されるのは、入れ子の子リストを持たない leaf のリスト項目で、1行で完結するものと、（自身の継続部分内の空行を含め）複数行にわたるものの両方です。unordered・task-list・ordered のいずれにも適用されます。項目が次のいずれかに該当する場合は、構造化コントロールなしの生のMarkdown行にフォールバックします。すなわち、list member と callout/blockquote member にきれいに分割できない拡張ブロックの一部である場合、継続部分に入れ子の callout・blockquote・fenced code block・table・thematic break を含む場合、継続行のインデントが項目本体より浅い場合、あるいはノート自身のパーサーで単一のリスト項目として安全に還元できないその他の場合です。このフォールバックは意図的なもので、ブロックの本当の境界を確信を持って解決できないときに編集を推測したり無理に通したりすることはありません。順序付きリストの兄弟の番号も、自動的には振り直されません。

#### 親項目とその直接の子を編集する

自身の子を持つリスト項目を開くと、その項目自身のテキストは上記と同じ構造化・マーカーフリーエディタで表示され、その直下に直接の子が、読み取り専用のライブプレビューとしてすぐ下に表示されます。ここから、ペインを離れずに次のことができます。

- プレビュー内の任意の子（または孫）に移動し、それをペインの新しい対象として開く。
- プレビュー内で、対象となる直接の子を一度に1つずつインライン編集する。
- 直接の子リストの末尾に、新しい空の子を追加する。
- 対象となる直接の子を削除する（確認ダイアログあり）。
- 空行で区切られていない限り、上下ボタンで直接の子を並べ替える。
- 対象となる直接の子を直前の兄弟へインデントする、または孫を1段階だけ直接の子へアウトデントする。
- まだ子を持たない leaf 項目に、そのleaf自身のエディタから直接、最初の子を追加する。

これらはすべて、親自身のテキストとともに1回の Apply でまとめて保存されます。ただしインデント/アウトデントだけは例外で、同じ Apply 内で追加・削除・並べ替え・子のインライン編集と組み合わせることはできません（親自身のテキスト編集とは組み合わせ可能です）。インライン編集・削除・インデント/アウトデントによる移動ができるのは、自身に孫を持たない leaf の直接の子だけです。それ自身が子を持つ子は、さらに深く進むためには自身の対象として開く必要があります。親の最後に残った子を削除すると、その項目は自身の leaf エディタに戻ります。leaf に最初の子を追加すると、その項目は親に昇格し、同じ子プレビューとコントロールがすぐに利用できるようになります。

#### Outline Tree と Partial Edit Pane それぞれの役割

**Outline Tree View** は、ノート全体の構造を再編成する場所です。ドラッグ＆ドロップや move/indent/outdent コマンドによる、階層をまたいだ親子関係変更を含むセクション・リスト部分木の並べ替え、行のその場でのリネーム、クリックまたはキーボードによるナビゲーションを行います。上記のマーカーフリーな本文編集は提供せず、子自身のテキストをインラインで編集することもできません。

**Partial Edit Pane** は、一度に1つのブロックとその直接の子に対象を限定します。ブロックを兄弟に対して相対移動したり、任意に選んだ別の祖先の下へ親子関係を変更したり、まず移動せずに孫をその場で編集したりすることはできません――これらは引き続き Outline Tree の操作です。

単体の callout・blockquote、および拡張ブロック自身の行は、Partial Edit Pane でそれぞれ専用の構造化・prefixフリーエディタとして開きます（callout/blockquote では title・type・fold marker・本文が別々に編集されます。拡張ブロックの list member は、単体のリスト項目と同様にマーカーが隠されます）。拡張ブロックについては、ブロックの構造が分割可能な形である限り、list member とそれに続く callout/blockquote member をまとめて1回の Apply で編集・保存できます。対応していない形の場合は、従来どおりブロック全体を1つの生Markdownエディタで編集するフォールバックになります。

### 見出し行だけを操作する

**Move heading label up/down** と **Indent/Outdent heading level** は、現在の見出し行だけを変更します。その見出しの本文や子セクションは移動しません。通常の再編成には block 系コマンドを使い、意図的に見出し行だけを変更したい場合に限って使用してください。

## 設定

**設定 → コミュニティプラグイン → Unified Outliner** を開きます。**全般**（General）タブは次のように分類されています（括弧内は英語 UI での名前です）。

- **表示言語**（Language）: 自動（Obsidian本体の言語設定に従う）、日本語、または English。プラグイン自身のUI表示にのみ影響します。
- **アウトラインツリーの既定のサイドバー位置**（Outline Tree default sidebar）: 右（既定）または左。新規に開く Outline Tree View の位置のみに影響し、すでに開いている（手動で移動したものを含む）ツリーは移動しません。ツリーを左サイドバーに置くと右サイドバーが空くため、上のスクリーンショットのような3ペイン構成にできます。

**アウトラインツリーの表示内容**

- **アウトラインツリーにリスト項目を表示**（Show list items in Outline Tree View）: リスト項目をツリーに表示します。
- **本文段落も Outline Tree に表示する**（Show body paragraphs in Outline Tree View）: 本文の通常の段落を ¶ マーク付きのナビゲーションノードとして表示します。トップレベルおよびセクション直下の段落は、ツリーから編集・挿入・削除・移動・コピー・ミラーの作成も行えます（上記参照）。既定ではオフです。
- **アウトラインツリーにコードブロックを表示**（Show fenced code blocks in Outline Tree View）: 単体の fenced code block（Mermaid・Dataview・DataviewJS を含む）を、言語名と本文最初の行をラベルとした読み取り専用の行としてツリーに表示します。クリックすると開始フェンス行へ移動します。ツリー上でのリネームの対象にはなりませんが、専用の右クリックメニューから Move up/down・削除・Partial Edit で開く・コピー／複製・ミラーの作成に対応し、ドラッグハンドルによるドラッグ＆ドロップ（セクションをまたぐ移動を含む）にも対応します（上記「callout・blockquote・拡張ブロックを編集する」参照）。既定ではオフです。
- **アウトラインツリーに表を表示**（Show tables in Outline Tree View）: 単体の Markdown 表を、ヘッダー列名をラベルとした読み取り専用の行としてツリーに表示します。クリックするとヘッダー行へ移動します。ツリー上でのリネームの対象にはなりませんが、専用の右クリックメニューから Move up/down・削除・コピー／複製・ミラーの作成・Partial Edit で開く、に対応し、ドラッグ＆ドロップ（セクションをまたぐ移動を含む）にも対応します。Partial Edit では **Raw** タブと **Table** タブが表示され、Raw タブは表全体（ヘッダー行〜最終データ行）を生Markdownとして編集し（Apply時に構造検証あり、崩れる編集は拒否されノートは変更されません）、Table タブは各セル・行・列を直接編集できます。既定ではオフです。
- **アウトラインツリーにミラー（埋め込み）を表示**（Show mirror embeds in Outline Tree）: 同じノート内への埋め込み行（`![[#見出し]]` または `![[#^block-id]]`）を、読み取り専用の **⧉ Mirror:** 行として表示します（上記「ミラー（同じノート内の埋め込み）」参照）。既定はオフであり、オフのときは埋め込み行は通常の段落として表示されます。

**アウトラインツリーの見た目**

- **アウトラインツリーのセクション背景スタイル**（Section background style in Outline Tree）: セクション行をリスト行と見分けやすくする表示（背景／左端ストライプ／オフ）を選びます。
- **アウトラインツリーのリスト行強調スタイル**（List row highlight style in Outline Tree）: ホバー時のみ（既定）、常時薄い背景、オフから選びます。
- **アウトラインツリーの見出しprefix**（Heading prefix in Outline Tree）: 既定はオフ。「H1」〜「H6」、またはATX記号そのもの（「#」〜「######」）を選べます。見た目のみの設定で、見出しテキスト自体は変更しません。
- **アウトラインツリーのリストmarker**（List marker in Outline Tree）: 各リスト項目の前に、Markdownのリストマーカー（`-`、`*`、`+`、`1.` など）を表示します。既定では非表示です。

**移動操作**

- **セクションをまたぐリスト移動を許可**（Allow list moves across sections）: ルートレベルのリスト項目を、見出しセクションの境界を越えて移動できるようにします。
- **アウトラインツリーで移動先をプレビュー**（Preview move target in Outline Tree）: move系コマンドが実際に操作したブロックを一瞬フラッシュ表示します。
- **移動結果の通知を表示**（Show notification after moving）: move系コマンド実行後に、何を移動したかを示す通知を表示します。

**編集・操作**

- **順序付きリストのマーカーを「1.」に正規化**（Normalize ordered list markers to "1."）: 構造編集後に、順序付きリストの番号記号を `1.` に統一します。
- **キーボード選択を本文エディタに追従させる**（Follow keyboard selection into body editor）: キーボードでツリーを移動すると、本文エディタも追従します。
- **アウトラインツリーの折りたたみをエディタに同期**（Sync Outline Tree folding to editor）: ツリーでノードを折りたたむ／展開すると、本文エディタ側の該当箇所も連動して折りたたみ／展開します。
  折りたたむ対象がある行にはトグルが表示されます。見出しの直下が本文・表・コードブロックのみで、下位見出しがない場合も対象です（本文が空の見出しは対象外）。
- **無操作時の通知を表示**（Show no-op notices）: 実行できない操作が変更を行わなかった理由を表示します。

設定は **全般**（上記のとおりカテゴリごとに分類）と **拡張ブロック**（Extended blocks）の2タブに分かれています。**拡張ブロック** タブは、プラグイン組み込みの **List + Callout** と **List + Quote** のグループ化規則（詳しくは上記「callout・blockquote・拡張ブロックを編集する」を参照）を個別に有効・無効化するものです。規則を無効にしてもグループ表示が止まるだけで、Markdown本体や、まとめられているリスト項目・callout/blockquote自体は変更されません。

### Style Settings で見た目をカスタマイズする

[Style Settings](https://github.com/community-archive/obsidian-style-settings) コミュニティプラグインを導入すると、上記のトグル項目だけでなく、CSSを直接編集せずに Outline Tree View の見た目を調整できます。**設定 → Style Settings → Outline Tree View – Appearance** から、ライトモード・ダークモードそれぞれ個別に次を調整できます。

- ツリーの見出しラベルの**フォントサイズ**。
- Outline Tree View パネルの**背景色**。
- **文字色**、**目立たせない文字色**（空状態メッセージなどの補助的なテキスト）、**リスト項目の文字色**。
- **ハイライトされたノードの色**（本文エディタのカーソル位置に対応する行）と、**キーボード選択の背景色**（キーボード操作で選択中の行）。
- **セクション行の背景色**と**リスト行の背景色**（上記のハイライトスタイルで使われる色）。
- **move対象プレビューのフラッシュ色**（move系コマンド実行後に一瞬表示される色）。

## 安全に使うために

構造編集はMarkdownのテキストを変更します。通常のVaultバックアップを維持し、独自記法や複雑なMarkdownを含むノートでは、反映後に結果を確認してください。

- Unified Outliner はアクティブなノート内だけで動作し、ノート間で内容を移動・コピーしません。貼り付けできるのも、ブロックをコピーしたノートの中だけです。
- frontmatterはすべての構造操作の対象外です。
- 単体の callout・blockquote、および拡張ブロック（**List + Callout**/**List + Quote**）は、Outline Tree View から直接move・削除・ドラッグ＆ドロップ（セクションをまたぐ移動を含む）・Partial Edit Paneでの編集ができます（上記の視覚ガイドおよび「選択したブロックに焦点を当てて編集する」を参照）。拡張ブロックの2つのmemberは、その構造がきれいに分割できる限り、まとめて1回の Apply で編集・保存されます。単体の fenced code block（Mermaidを含む）または table は、設定で有効にすると Outline Tree 上に読み取り専用の行として表示され、そこから move（同一セクション内の前後兄弟との入れ替え）・削除（ブロック全体を一括）・ドラッグ＆ドロップ（セクションをまたぐ移動を含む）・Partial Edit Pane での編集ができます——fenced code block はフェンス行が非表示化され、言語は上部の専用選択UIで別途指定します。table は Raw タブと Table タブで開き、Table タブではセル・行・列を直接編集できます（Apply時に構造検証あり、崩れる編集は拒否されノートは変更されません）。本文エディタ側でカーソルがその内部にある状態であれば、**Move block** はいずれの種別についても、Outline Tree の表示設定に関わらずブロック全体を移動できます。
- Partial Edit Pane から親のリスト項目の直接の子を編集する操作（追加・削除・並べ替え・インライン編集・インデント/アウトデント）は、leaf の子――自身に孫を持つ子は、その子自身の対象として開く必要があります――に限られ、インデント/アウトデントは一度に1段階までです。1回の Apply でどこまで組み合わせられるかは、上記の「親項目とその直接の子を編集する」を参照してください。
- コピー・複製・貼り付けは行を挿入するだけであり、コピー元を含む既存の行は一切書き換えません。順序付きリストの番号も振り直しません。コピー後にコピー元が変更された場合や、貼り付け位置がコピー元・拡張ブロック・frontmatter・コードブロック・callout の内部になる場合は拒否します。
- ミラーは、同じノート内の見出しとブロックを参照する Obsidian の通常の埋め込みであり、別のデータベースは持ちません。ミラーの作成で追加されるのは、参照先のブロック ID（`^uo-…`。まだない場合のみ）と埋め込み行だけであり、循環参照になる場合は作成を拒否します。ミラーの削除で取り除かれるのは埋め込み行（とその前後の余分な空行）だけであり、参照先の見出しやブロックと、そのブロック ID は一切変更しません。ミラー行はそれ以外の点では読み取り専用であり、リネーム・ドラッグ・コピー・ミラー経由の編集はできません。
- 集中編集は、読み込み後に元の対象領域が変更されていない場合にだけ適用されます。ペインを未保存の変更なしに開いたまま他の場所でノートが変更された場合は、古い内容を表示し続けるのではなく、自動的に再同期します。

## ロードマップ

バージョン 1.0 で、単一ノートの構造編集というこのプラグインの中核的な範囲がそろいました。すなわち、構造的な move・レベル変更コマンド、Outline Tree でのナビゲーション・リネーム・ドラッグ＆ドロップ（セクションをまたぐ移動を含む）・挿入、リスト項目とその直接の子（追加・削除・並べ替え・インデント/アウトデント・インライン編集、一度に1段階まで）の構造化・マーカーフリー編集と、callout・blockquote・拡張ブロック・fenced code block・table（Table モードを含む）の構造化エディタを備えた Partial Edit Pane、ブロックのコピー（コピー・複製・貼り付け）、そして同じノート内のミラー（表示・作成・移動・削除と、ブロックを参照しているミラーの確認）です。

**Move up/down** コマンド自体のセクション越え対応、任意の深さ・任意の親への自由な移動、1段階を超える部分木単位の操作、Partial Edit Pane 内でのドラッグ＆ドロップ、より踏み込んだ fenced code block の編集、そしてミラーについては、ミラー行を通じた編集、ミラー行のドラッグ＆ドロップ、他のノートへのミラーは、いずれも今後の課題であり、着手していません。

後続の方向性と、意図的に対象外とする機能は、簡潔な[ロードマップ](ROADMAP.ja.md)を参照してください。
