# Phase 5A-1「Partial Edit Pane の stale 状態検知・安全な再読み込み」実機受入テスト

本ドキュメントは、実装担当（Claude）が Phase 5A-1 本体および hardening（自己Apply抑止・段落読み取り専用リゾルバ・fail-closed処理・純粋関数分離）の完了後、開発指示者が実機（Obsidian）上で実施するための、具体的な操作手順である。実装内容そのものの解説文書ではなく、実際に手を動かして確認するための手順書として作成した。

## 1. 目的と対象範囲

本ドキュメントの目的は、`src/view/PartialEditView.ts`・`src/edit/paragraphPartialEdit.ts`・`src/view/partialEditSyncClassification.ts`・`src/i18n.ts`・`styles.css` に実装済みの Partial Edit Pane の stale（内容が古い）状態検知、clean な Pane の自動追従、dirty な Pane の保護、明示的な Reload、対象ノートのリネーム・削除への追従という一連の機能について、開発指示者が実機の Obsidian 上で合否を判定できる、具体的な操作手順を提供することである。

対象範囲は、Phase 5A-1 の元設計（`docs/phase5a1_partial_edit_stale_pane_synchronization_design.md`）と、そのうえで実施した hardening（自己Apply中のイベント抑止、段落の読み取り専用再解決、`vault.cachedRead` 失敗時のfail-closed化、純粋関数への分離、および段落anchor再解決契約の構造的拡張＝Pass 3によるstale/Reload復帰 hardening）の双方である。本文中の各テストは、いずれもこのワークツリーの現在の実装を読み取り専用で再確認したうえで作成しており、未実装の挙動や推測による記述は含まない。環境依存で Claude 自身が確認できない項目（モバイル・popout・スクリーンリーダーでの見た目や挙動など）は、その旨を明記し、任意項目として「未確認」と記録できるようにしてある。

なお、本ドキュメントは Mac 上でのモバイルエミュレーションによる確認は対象としない。実機（iPad・iPhone・Android・macOS 上の Obsidian）そのものでの確認を前提とする。

**段落anchor再解決契約の拡張（hardening §5、Pass 3）に関する注記**: 3節のテスト用ノートの「サブセクションA」は最初から2つの独立した段落を含んでいる。A-1／A-2／A-3／G-3（対象段落自身の内容変更・Undo・Redoへのclean-Pane自動追従）、C-1／C-3（Reloadによる復帰）、F-1（複数Pane間の同期）は、いずれもこの2段落構成のセクションを対象とするため、対象段落自身の内容だけが変化した場合の安全な再解決には、`src/edit/paragraphPartialEdit.ts`の`resolveParagraphAnchorText`が新たに備えたPass 3（同一parent/depth配下の段落の母数・位置・重複の有無・直前直後の段落本文が anchor構築時と一致することを条件とする、読み取り専用の構造的フォールバック）が用いられる。これらのテストの期待結果は、このPass 3が正しく機能していることを前提として記述している。一方、対象段落の前後への挿入・隣接段落の削除・split・merge・reorder・parentId/depthの変更・重複内容の段落が絡むケースは、Pass 3の対象外として意図的に安全側（stale維持またはReload失敗によるunavailable）のままである——これは既知の仕様上の制約であり、fixtureを縮小したり、この制約を隠したりする形での対応は行っていない。永続的な段落ID、または内容の類似度に基づく推測は一切実装されていない（実装されているのは、母数・位置・直前直後本文・重複有無という、あくまで構造的な情報のみに基づく再解決である）。詳細は`docs/phase5a1_partial_edit_stale_pane_synchronization_design.md`9.5節を参照。

## 4. 共通の確認方法

- Partial Edit Pane を開くには、Outline Tree View 上で対象のノード（見出し・リスト項目・スタンドアロンのコールアウト／引用）を右クリックし、「部分編集ペインを開く」を選ぶ。段落の場合は対象の段落を右クリックし「段落を編集…」を選ぶ。CompositeBlockとして認識された画像+コールアウトの組は、そのリスト項目を右クリックし「拡張ブロックを部分編集ペインで開く」を選ぶ。
- Pane の状態は、ヘッダー（タイトルとApply/Cancelボタンの行）のすぐ下、パンくず（breadcrumb）の上に表示される「同期状態行」で確認する。何も表示されていなければ同期済み（synced）である。表示が出ている場合、文言が「Unified Outliner: 本文が変更されたため、このペインの内容は現在の本文と一致していません。」であれば stale、「Unified Outliner: 編集対象が見つからないため、このペインでは編集できません。」であれば unavailable である（いずれも2026-09-08のUX修正で文言更新済み）。この行には「再読み込み」ボタンも表示される。
- Apply ボタンは、Pane に未適用の編集がある（dirty）ときのみ表示される。stale または unavailable の間は、Apply ボタンが表示されていても無効化（クリックできない）状態になり、ボタンにカーソルを合わせる（またはフォーカスする）と、無効化理由のツールチップ（stale時「このペインの内容が古いため、適用は無効になっている。再読み込みしてから編集し直すこと。」／unavailable時「この内容が見つからないため、適用は無効になっている。再読み込みするか、このペインを閉じて開き直すこと。」）が表示される。
- 本文側での変更（直接編集・Undo・Redo・他Paneからの適用・ファイルのリネーム・削除など）は、Pane側で即座にではなく、概ね0.2秒未満の短い遅延ののちに反映される。反映が確認できない場合は、対象のノートを一度アクティブにする（タブを切り替えるなど）か、数秒待ってから再確認する。
- 各テストは、原則として直前のテストの影響が残らないよう、Partial Edit Pane を一度閉じて対象ノードを開き直した状態から始める。開き直す際は、対象ノートの内容がテスト用ノートの初期状態（3節）に戻っていることを確認する。
- 実施結果欄には「合格」「不合格」「未確認」のいずれかを記入する。「未確認」は、環境上の制約（popout非対応・スクリーンリーダー未搭載など）でその場では確認できなかった場合、または3節・2節で述べた前提が満たせなかった場合にのみ用いる。

以下をすべて満たした場合に、Phase 5A-1（本体およびhardening）の実機受入を合格とする。

- Dグループ（自己Apply後の誤検知抑止）のすべてのテストが合格していること。ここが1件でも不合格の場合、他が全て合格していても全体を不合格として扱う。
