# Partial Edit Pane の移動に本文エディタを追従させる 実機受け入れテスト（2026-09-30）

設計は `docs/統合実装ロードマップ_2026-08-05.md` §3.34 を参照する。対象ノートの例は `ipad-test/Iriai/70000001_0018_裁判書 村境争論ノ控訴0.md`（image-ocr 17 組）と、見出し・入れ子リストを含む任意のノートである。

## 1. 設定 ON（既定）

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 設定画面の「編集・操作」を開く | 「部分編集ペインでの移動に本文エディタを追従させる」がキーボード選択の設定の直後にあり、既定で ON になっている |
| 2 | Tree から list 項目を部分編集で開く | Tree クリックによる通常の本文移動だけが起きる（Pane からの追加の移動はない） |
| 3 | Pane の「次へ」「前へ」（兄弟）を押す | Pane が切り替わり、本文も移動先の行が上端に来るようスクロールしてカーソルが移る。フォーカスは Pane 側に残る |
| 4 | パンくずの段を押す | 本文が該当する見出しや親 list へ移動する |
| 5 | Subtree Navigator のチップ（および「More…」の項目）を押す | 本文が該当する子へ移動する |
| 6 | 親 list 項目の子プレビュー行を押す | 本文が該当する子へ移動する |
| 7 | image-ocr を開き、次へ／前へで数回移動する | 各移動で本文が該当する画像行へ移動する。画像の読み込み後も位置がずれない |
| 8 | 未保存の変更がある状態で 3〜7 のいずれかを行い、ダイアログで閉じる（キャンセル） | Pane も本文も動かない。draft は残る |
| 9 | 8 で Apply または破棄を選ぶ | 移動が成立し、本文も移動する |
| 10 | Pane で Apply する／本文側で開いている対象を書き換えて自動再読込させる／Reload ボタンを押す | 本文のスクロールやカーソルは Pane によって動かされない |
| 11 | 先頭の image-ocr で「前へ」を押そうとする | ボタンは無効で、何も起きない |
| 12 | Pane をポップアウトしてから 3〜7 を行う | メインウィンドウの本文が移動する。例外やエラーは出ない |
| 13 | Pane が読み込んだノートとは別のノートを本文でアクティブにしてから 3 を行う | Pane 側の切り替わり方は既存の挙動のままである。本文の移動は、Pane が読み込んだノートとアクティブなノートが一致する場合に限って起きる |
| 14 | iPad で 3・4・7 を行う | タップで同様に動く |

## 2. 設定 OFF

| # | 操作 | 期待結果 |
|---|---|---|
| 15 | 設定を OFF にして 3〜7 を行う | Pane だけが切り替わり、本文のスクロールやカーソルは動かない |
| 16 | OFF のまま Tree の行をクリックする | Tree からの本文移動は従来どおり動く（この設定の影響を受けない） |

## 確認結果

- 2026-09-30：利用者が実機で確認し、全項目正常（Pass）。1.0.3 でリリースした。
