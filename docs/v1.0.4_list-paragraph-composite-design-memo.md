# v1.0.4 設計メモ — list + paragraph の CompositeBlock 認識と段落 block ID の読み取り

## 1. 目的と範囲

single-line-list の直後に、その list item の子として成立する paragraph が空行なしで続く場合、両者を CompositeBlock（規則 ID `list-paragraph`）として認識する。また、その paragraph に既存の Obsidian block ID が書かれていれば、それを構造情報として保持する。

これは将来の Phase 6 が「list + paragraph」を意味抽出候補とし、paragraph 側の既存 block ID を安定アンカー候補として参照するための基盤である。ただし v1.0.4 は Phase 6 のいかなる処理にも接続しない。

## 2. 規則の位置づけ（tree-read-only）

- `STRUCTURAL_COMPOSITE_BLOCK_RULES`（`src/model/compositeBlock.ts`）に `list-paragraph` を置いている。設定は `geometry: "list-child-continuation"`、`treeReadOnly: true`、prefix `≡` である。
- 第 1 段階（認識専用）の後、第 2 段階で Outline Tree への投影と Partial Edit を追加した。`treeReadOnly` の規則は Tree に読み取り専用で投影され、Partial Edit Pane で開けるが、まとまりとしての移動・ドラッグ・削除・字下げ・コピーは一切できない。
- 規則の集合は 2 つある。`getEnabledCompositeBlockRules`（image-ocr / image-quote のみ）は、移動・ドラッグ・削除・コピー・挿入・エディタコマンドが使う。`getEnabledTreeCompositeBlockRules`（全規則）は、Tree の投影と Partial Edit のみが使う。
- 評価順序は、既存の adjacent-sequence 規則が先、list-child-continuation 規則が後である。先行規則で使われた member は後続規則では使わない（先勝ち）。adjacent-sequence の結果は従来どおり `composite-N` の id を持ち、新規則の結果は `composite-list-paragraph-N` の id を持つ。このため、2 つの規則集合を併用しても既存 composite の id は一致し、OutlineTreeView の操作系（currentComposites）が誤った composite を指すことはない。

## 3. list + paragraph が成立する厳密な条件

list item L と paragraph P は、次のすべてを満たすときに限り 1 つの CompositeBlock になる。

1. P は `scanComplexBlocks` が返す paragraph で、`editability === "supported"` である（重複や境界曖昧で降格されていない）。
2. `P.parentId === L.id` である。すなわち 5P の契約により、P の各行が L の本文開始列まで字下げされている。字下げ不足の段落は section の子、または L の不可視の継続行であり、対象外である。
3. `P.range.startLine === L.range.startLine + 1` である。L 自身の本文はマーカー行の 1 行のみで、L と P の間に空行も他の行もない。
4. P が L の唯一の内容である。`P.range.endLine === L.range.endLine` かつ L は子 list item を持たない。空行を挟む 2 つ目の段落、入れ子の callout、子リストなどを含む list item は対象外である（最初の段落のみを扱い、それ以外が混在する場合は束ねない）。
5. L の `unsafeIndent` が false である。
6. P 以外のいかなる complex block も L の範囲と重ならない。
7. L と P は同一 section に属する（見出しをまたがない）。
8. L も P も、先行規則の CompositeBlock の member ではない。

member の range は、list member が L のマーカー行のみ、paragraph member が P.range である。両者は隣接し、重ならない。CompositeBlock 全体の range は L.range と一致する。

## 4. paragraph の既存 block ID

- `CompositeBlockMember.blockId?: string | null` を追加した。paragraph member では既存 ID（キャレットなし）または `null`、それ以外の member では未定義である。
- `getCompositeParagraphBlockId(composite)` は最初の paragraph member の `blockId` を返し、無ければ `null` を返す。
- 読み取りは `src/parser/blockIdInRange.ts` の `readBlockIdWithinRange` が行う。認識する形は、Block ID 欄・ミラーと同じ規則（`edit/partialEdit.ts` の `detectBlockIdLayout`）のうち、範囲内の 2 形だけである。
  - 段落の最終行末尾の ` ^id`（本文を伴う場合）
  - 段落自身の最終行が単独の `^id` 行である場合（段落が 2 行以上の場合）
- 段落範囲の外（後続の単独 `^id` 行、list マーカー行、CompositeBlock 全体の末尾）からは推測しない。行中の `^word`、`x^2`、閉じたコードスパン内の `^` は ID とみなさない。
- ID の新規発行、Markdown への書き込み、ensureBlockId は一切行わない。

## 5. 設定

`CompositeBlockSettings.listParagraph`（既定 true）を追加し、Settings → Composite blocks に切り替えを 1 つ追加した。v1.0.3 以前の data.json にキーが無い場合は true として補完される。切り替えると開いている Outline Tree が再描画される。

規則名は UI 言語にかかわらず英語に統一した。Tree の composite 行と設定の規則名は、それぞれ Image + OCR（image-ocr、旧 List + Callout）、Image + Quote（image-quote、旧 List + Quote）、List + Paragraph である。設定キーと保存形式は変更していない。fold identity はラベルに基づくため、Image + OCR / Image + Quote 行の折りたたみ状態は更新後に一度だけ展開状態に戻る。

**1.0.5 での訂正**：1.0.4 では image-ocr / image-quote の規則名を「Image + OCR」「Image + Quote」としたが、これは Phase 5D-1L で汎用化のために「List + Callout」「List + Quote」へ改めた経緯に反する誤りであった。1.0.5 で、設定・Outline Tree・部分編集ペインのいずれでも「List + Callout」「List + Quote」に戻した（英語表記の統一は維持し、List + Paragraph は変更なし）。

## 5a. Outline Tree への投影（第 2 段階）

- 一般機構（`buildOutlineTree` の composite 投影、`isCompositeSafelyProjectable`、`collectReadOnlyOutlineNodeIds`、foldIdentity の composite / complex-member 分岐）をそのまま通す。親行は prefix span（`≡`）と表示名 span に分けて描画される。
- 子行の扱い。list member は元の list 行として表示する。paragraph member は complex-member（`complexKind: "paragraph"`、prefix `¶ `）の読み取り専用行として表示する。ラベルは段落本文の最初の意味のあるテキストである。単独の `^id` 行と段落自身の行末 ID は除き、何も残らない場合は英語の `Paragraph` とする。
- 投影された composite の段落は、通常の段落行としては表示しない（二重表示を防ぐ）。安全確認に通らず投影されない composite の段落は、通常どおり段落行として表示される。
- 新しいノード属性 `OutlineTreeCompositeNode.allowsStructuralOps` は、image-ocr / image-quote では true、list-paragraph では false である。OutlineTreeView は、これが true の composite 行に限ってドラッグハンドル・D&D・移動 / 削除 / コピーのメニューを付ける。false の親行と各 member 行の右クリック・長押しメニューは、「Open in Partial Edit」の 1 項目だけである。rename は従来どおり `beginRenameForNode` の種別ガードと読み取り専用ガードで拒否される。
- カーソルが段落内にある場合は、paragraph member 行をハイライトする。list 行にある場合は、list member 行をハイライトする。
- 認識条件が崩れると、次回の refresh で composite が消え、通常の list / paragraph の表示に戻る。状態の保存や本文の書き換えは行わない。

## 5b. Partial Edit（第 2 段階）

- 入口は、Tree の親行・member 行の「Open in Partial Edit」である（既存の `activatePartialEditViewForComposite`）。
- 表示順は、list 行、段落本文（共通の字下げと block ID を除く）、Block ID 欄（読み取り専用）である。list 行は Image + OCR の list 行と同じ `buildCompositeListMemberProjection` で marker を除いて表示し、Apply 時に `invertListMarkerProjection` で marker を戻す。投影できない形の行は、生の 1 行のまま表示する。純粋モジュールは `src/edit/listParagraphCompositeProjection.ts` である。
- Apply の処理は次の順で行う。
  1. `composeListParagraphText` が、本文の各非空行に元の字下げを戻し、末尾の空行を除いたうえで、block ID を元の形（行末の ` ^id` は元の空白を含めて、単独行は元の行そのまま）で段落の最終行に付け直す。
  2. `verifyBlockIdStaysInParagraph` が、合成後のノート全体で ID が信頼できる段落の最終行にあることを確認する。満たさない場合は書き込み前に拒否し、Notice を出す。
  3. 既存の `applyCompositeBlockEdit` が、競合確認と 1 回の置換を行う。
- 無編集の Apply はバイト単位で同一になる。ID の無い段落に ID を追加することはない。開閉だけでは本文は変わらない。
- 空行の挿入、list marker の削除など、ID の位置を壊さない構造変更は入力どおりに保存し、composite は解消される（既存の「拡張ブロックではなくなった」Notice が出る）。
- 投影が成立しない例外的な形の場合は、既存の範囲全体の生テキスト編集に戻る。その場合も、元の段落に ID があれば、Apply 時にその ID が編集範囲内のいずれかの段落の ID として残ることを確認する（`blockIdKeptInParagraphWithin`）。
- image-ocr / image-quote / callout / blockquote の Partial Edit は変更していない。composite の再解決に使う規則集合だけを Tree 用に揃えた（snapshot は id を照合に使わないため、既存の composite には影響しない）。

## 9. 表示名の変更（1.0.5 以後）

規則名を「List item + Paragraph」から「List + Paragraph」に改めた。List + Callout / List + Quote と揃えるためで、設定・Outline Tree・部分編集ペインのすべてに適用する。規則 ID（`list-paragraph`）・設定キー・動作は変更していない。本メモの本文中の規則名も新しい名称に置き換えた。

## 10. 1.0.6 での変更

- 段落の Block ID は、読み取り専用の表示をやめ、通常の Block ID 欄で変更・削除できるようにした。元の形のまま段落の末尾に書き戻すこと、リスト行へ移さないこと、自動で発行しないことは変わらない。詳細は `docs/v1.0.6_partial-edit-editors-design-memo.md` の §5 を参照。
- 部分編集ペインのリスト枠は、marker なしの折り返し表示の枠になり、内容に合わせた高さとリサイズ用のつまみを備えた（同メモ §3）。
