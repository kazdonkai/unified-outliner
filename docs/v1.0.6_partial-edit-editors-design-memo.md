# 1.0.6 設計メモ — 部分編集ペインの編集枠・Block ID・List + Paragraph 名称

## 1. 範囲

1.0.6 は UI の修正版である。規則 ID、設定キー、Markdown の解析・書き込み規則は変更していない。

1. 拡張ブロック規則名の変更：「List item + Paragraph」を「List + Paragraph」に改めた。
2. 部分編集ペインの編集枠を、内容に合わせた高さにし、右下にリサイズ用のつまみを付けた。
3. 編集枠と Block ID 欄の背景を常時同じ見た目にし、Style Settings で個別に設定できるようにした。
4. List + Paragraph の段落の Block ID を、通常の Block ID 欄で編集できるようにした。
5. iPad で、日本語入力や Block ID 欄の入力が正しく判定されるようにした。

## 2. 規則名

- 設定・Outline Tree・部分編集ペインの規則名は、どの UI 言語でも「List + Callout」「List + Quote」「List + Paragraph」である。
- fold identity はラベルに基づくため、旧名称のときに折りたたんでいた List + Paragraph 行は、更新後に一度だけ展開状態に戻る。

## 3. 編集枠の大きさ

| 対象 | 開いたときの高さ | つまみ |
|---|---|---|
| 拡張ブロックのリスト枠 | 文字量＋1行（最低2行） | あり |
| 拡張ブロックの下部の枠（callout・quote・段落） | 文字量＋1行（最低3行、ペインの7割まで） | あり |
| 単体の callout・blockquote・fenced code・table（Raw タブ）・段落 | 同上 | あり |
| 見出しセクション・リスト部分木 | ペインいっぱい（従来どおり） | あり |

- 拡張ブロックのリスト枠は、1行の input を折り返し表示の textarea に変えた。Enter は入らず（IME の変換確定中を除く）、貼り付けた改行は空白に置き換わる。そのため、リスト member は常に1行のままである。
- 高さは `fitTextareaToContent` が計算する（`src/view/PartialEditView.ts`）。文字の入力に合わせて伸びる。
- つまみ（`attachResizeGrip`）は pointer events とポインタキャプチャで実装している。iPad では標準の textarea リサイズハンドルが使えないためである。つまみで高さを変えると、そのブロックの間はその高さを保つ。別のブロックを読み込むと、文字量に合わせた高さ（見出し・リストはペインいっぱい）に戻る。
- 本文枠のつまみは本文枠の直後の要素である。CSS の兄弟セレクタにより、本文枠が隠れると（Table Mode など）つまみも隠れる。

## 4. 背景色と Style Settings

- リスト枠は、焦点の有無にかかわらず、常に本文枠と同じ背景・枠線で表示する。
- Block ID 欄は、Obsidian 標準の入力欄の見た目（iPad では灰色の丸いピル型）をやめ、プラグイン独自の見た目（本文枠と同じ背景・枠線・角丸 4px）で表示する。`body … input.…` のセレクタで、`!important` を使わずに Obsidian モバイル版の書式より優先させている。
- Style Settings の「Partial Edit Pane – Editor Backgrounds」に、次の3色を追加した（ライト／ダーク別）。

| 設定名 | CSS 変数 | 未設定時 |
|---|---|---|
| Extended Block List Row Background | `--uo-partial-edit-list-bg` | Background Color |
| Body Editor Background | `--uo-partial-edit-body-bg` | Background Color |
| Block ID Field Background | `--uo-partial-edit-blockid-bg` | Body Editor Background → Background Color |

## 5. List + Paragraph の Block ID

- 1.0.4 では、段落の ID を保護するために Block ID 欄を読み取り専用にしていた。1.0.6 では、ほかのブロックと同じ通常の Block ID 欄で、ID を変更・削除できるようにした。欄は、段落に ID がある場合だけ表示される（ほかのブロックと同じ）。
- Apply 時の処理は次のとおりである。
  - `composeListParagraphText` が新しい ID を、元の形（行末の ` ^id` は元の空白を含めて、単独行は元の字下げのまま）で段落の末尾に付け直す。空欄にした場合は ID を削除する。
  - 不正な ID は「reason.invalid-block-id」で拒否する。
  - 書き込み前に、`verifyBlockIdStaysInParagraph` で新しい ID が段落の最終行にあることを確認する。
- ID を変更すると、同じノート内のミラー埋め込みも書き換わり、他のノートからの参照がある場合は警告が出る（ほかのブロックの Block ID 欄と同じ `prepareBlockIdRename` / `notifyBlockIdRename`）。composite の Apply は、書き換え前の本文（`liveLines`）との差分で書き込む。そのため、ID の変更と埋め込みの書き換えは1回の取り消しで元に戻せる。

## 6. iPad での入力

- リスト枠の Enter 抑止は、IME の変換確定を妨げないようにした。`isComposing` に加えて、compositionstart から compositionend の1ティック後まで有効な独自フラグで判定する。iPadOS では、確定の Enter の keydown が compositionend の後に来るためである。
- Block ID 欄は、input に加えて change、keyup、compositionend でも変更の有無を判定する。iPad で Block ID だけを変えたときに、適用ボタンが出ないことへの対策である。
